# The standing cameras, in one place for both tools that use them.
#
#   tools/views.sh    redraws these with the CPU drawing   (pictures/drawn-<name>.png)
#   tools/photos.sh   photographs these in a real browser  (pictures/<number>-<name>.png)
#
# One line per view: the name, where a visitor stands and what they look at as x,y,z,yaw,pitch
# (metres and radians; the Villa has -z as north, and a yaw of 0 looks south, 3.14 north), and a
# narrow eye angle where the wide one is
# no use — a "-" means the Villa's own 0.85 radians.
#
# `backstore` is the seventeenth, and it is there because the sixteen before it never looked at the
# back of the house east of the store room: stand on `rear`, 5 m off the north face, and every point
# of the store's own face projects outside the right edge of the picture (`tools/bandwhere.json`
# says OUT OF FRAME for x = 5.1 and everything east of it). So the store room's face — and the band
# of glass cut into it — was in no picture this folder takes. If a view comes and goes here the set no
# longer lines up by counting, so add new cameras at the end and never in the middle.
#
# Keep the two tools on these cameras: a browser picture and a drawing of the same place are the only
# way to tell a fault in the Villa from a fault in the drawing.
#
# Three of these stood in the watercourse when it was laid (`src/stream.js`) and were moved to dry ground.
# The watercourse has since been re-laid straight down the west of the garden, so `westlawn` had to move again:
# it stood at x -20 z 10, which is now the middle of the channel, and it now stands on the bank above it.

# from one of its ends.
